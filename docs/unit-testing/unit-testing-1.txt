================================================================================
FINSIGHT — TEST SUITE CATALOG (unit-testing-1)
================================================================================
Tài liệu liệt kê chi tiết toàn bộ test tự động của nền tảng FinSight: mỗi lớp
test, loại (unit / integration), số lượng test và những gì nó kiểm chứng.

Phạm vi tính đến: 9 microservice (api-gateway, auth, user, transaction, budget,
dashboard, risk, notification, analytics).

TỔNG QUAN CON SỐ
--------------------------------------------------------------------------------
- Tổng số test method (@Test / @ParameterizedTest):  434
- Tổng số lớp test:                                   93 (+ vài lớp base/support)
- Trong đó:
    * Unit / component test (chạy KHÔNG cần Docker):  ~253
    * Integration test (cần Docker – Testcontainers): ~181
- Framework: JUnit 5 (Jupiter) + Mockito + AssertJ.
- Integration test dùng Testcontainers (MySQL 8, Kafka KRaft, Redis) và WireMock
  (giả lập HTTP upstream), Awaitility (chờ bất đồng bộ).

PHÂN BIỆT UNIT vs INTEGRATION
--------------------------------------------------------------------------------
- UNIT test: kiểm thử một lớp logic ở trạng thái CÔ LẬP, phụ thuộc được mock bằng
  Mockito. Không khởi động Spring context, không cần Docker. Rất nhanh.
- COMPONENT/SLICE test: khởi động một phần Spring (ví dụ @WebMvcTest cho controller,
  hoặc gateway + WireMock), không dùng Testcontainers.
- INTEGRATION test: khởi động Spring đầy đủ + hạ tầng thật qua Testcontainers
  (MySQL/Kafka/Redis). Tên lớp kết thúc bằng "IntegrationTest".

CÁCH CHẠY
--------------------------------------------------------------------------------
- Mỗi service là 1 project Maven độc lập (không có aggregator pom).
- Chạy toàn bộ (unit + integration) cho 1 service:
      cd services/<service> && mvnw.cmd test            (Windows)
      cd services/<service> && ./mvnw verify            (Bash/Linux)
  ("verify" chạy cả unit lẫn integration vì integration test chạy qua Surefire.)
- Chạy 1 lớp:    mvnw.cmd test -Dtest=CurrencyValidatorTest
- Chạy 1 method: mvnw.cmd test -Dtest=CurrencyValidatorTest#rejectsUnknownCodes
- CI: GitHub Actions (.github/workflows/ci.yml) chạy `mvn verify` cho cả 9 service
  trên ma trận (JDK 21), Docker sẵn có nên Testcontainers hoạt động.

Quy ước chung của test:
- userId luôn lấy từ JWT (claim), không bao giờ từ request body → nhiều test kiểm
  chứng "tenant isolation" (user A không thấy dữ liệu user B).
- Soft delete: test kiểm chứng bản ghi đã xóa mềm bị ẩn khỏi truy vấn.
- Idempotency inbox (processed_events): test kiểm chứng sự kiện trùng chỉ xử lý 1 lần.
- Envelope API chuẩn { success, data, meta } / { success, error{code,message} }.
